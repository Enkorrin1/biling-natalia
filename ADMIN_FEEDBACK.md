# Замечания администратора из авыа1.xlsx

Источник — семь замечаний в таблице. Неясные формулировки не считаются согласованным техническим заданием.

| Пункт | Результат |
|---|---|
| Ручная регистрация | В «Участники и доступ» → «Добавить клиента» доступна выдача временного логина и пароля без email. При первом входе обязательны имя, компания, телефон, постоянный email и новый пароль. Данные сохраняются вместе со сменой пароля; прежние сессии отзываются. Срок временного доступа — 7 дней. |
| Оценка | Требует примера от администратора: не указано, какие именно элементы дублируются. Сейчас различаются плановые часы работы и фактически потраченное на подготовку оценки время. Формулы и согласование не менялись. |
| Просмотр пароля | Кнопка с глазом на входе, регистрации, активации/восстановлении, смене временных данных, создании сотрудника и в результате выдачи временного доступа. |
| Git и релизы | Клиентский интерфейс уже скрывал блок. Теперь клиент не запрашивает ссылки; API также запрещает их чтение клиентам. |
| Иерархия | Уже реализованы компании, роли владельца/участника/наблюдателя, проекты, заявки и группировка уведомлений по компаниям и проектам. Сотрудники исполнителя используют собственные командные роли. Отдельное назначение клиентского специалиста на проект пока не предусмотрено: клиентский доступ задаётся компанией и видимостью заявки. |
| Стоимость | Владелец или менеджер может включить «Скрывать стоимость от сотрудников компании». Участники и наблюдатели видят часы без ставки и сумм; счета, акты, печать документов и финансовые уведомления компании им недоступны. Владелец сохраняет доступ. По умолчанию существующее поведение сохраняется. |
| Битрикс | Пока требуется выбрать сценарий. Возможные требования для обсуждения: создание заявки из Битрикса; возврат статуса и ссылки на заявку; обмен комментариями; передача согласованных/фактических часов. Это варианты, а не обещание реализованной интеграции. Нужны точный продукт/редакция Битрикса, объекты обмена, направления и правила разрешения конфликтов. |

Настройка стоимости не удаляет ранее просмотренные документы и не фильтрует суммы, вручную написанные пользователями в сообщениях или приложенные к заявкам в файлах.

Проверки: `tests/test_admin_feedback.py` покрывает роли, закрытие финансовых API, восстановление доступа и внутренние Git-ссылки. Сценарий временных данных и сохранения контактов проверяется в `tests/test_flows.py`. Для визуальной проверки использована отдельная база `output/admin-feedback-review.db`; рабочая база не менялась.
